# ADR-009: 커밋 메시지 제안은 사용자가 고른 외부 명령에 맡기고 cyella는 비밀을 다루지 않는다

## 상태

승인됨 - 2026-11-22

## 배경

커밋 상자에서 staged 변경에 맞는 커밋 메시지를 AI에게 제안받고 싶다. 길은 둘이다. 사용자가 이미 설치해 로그인해 둔 AI CLI(Claude Code, Codex 등)를
띄우는 길과, API 키를 받아 HTTP로 직접 부르는 길이다. 뒤의 길은 키를 어디에 둘지를 먼저 정해야 하고
([ADR-004](ADR-004-askpass.md)·[ADR-007](ADR-007-hosting-integration.md)의 "cyella는 비밀을 저장하지 않는다"와 맞춰야 한다),
앞의 길은 cyella가 비밀을 전혀 만지지 않는다. 그래서 앞의 길을 먼저 만든다. 이 문서는 그 결정과 한계를 적는다. API 키 경로는 다루지 않는다.

## 결정

### 외부 명령

- **사용자가 정한 명령 하나를 자식 프로세스로 띄운다.** 프롬프트를 표준 입력으로 넘기고 표준 출력을 메시지로 받는다. 명령줄에 프롬프트를 싣지 않는다
  (길이 제한에 걸리고 프로세스 목록에 보인다). 실행은 [ADR-003](ADR-003-process-execution.md)의 실행기를 그대로 쓴다.
- **cyella는 그 명령의 로그인·키·토큰을 읽지도 저장하지도 않는다.** 누구의 계정으로 어디에 과금되는지는 그 명령이 정한다.
- **환경 변수는 건드리지 않는다.** 터미널에서 같은 명령을 돌릴 때와 같게 동작해야 한다. 예를 들어 `ANTHROPIC_API_KEY`가 있으면 `claude -p`는
  구독 로그인보다 그 키를 쓰는데, 이것도 사용자가 터미널에서 보는 동작 그대로다.
- **작업 폴더는 저장소가 아니다.** 앱의 로컬 데이터 폴더 아래 빈 폴더(`%LOCALAPPDATA%\cyella\suggest`)에서 띄운다. 저장소에서 띄우면 그 저장소의
  에이전트 설정 파일(`CLAUDE.md`, hook 등)이 명령에 끼어든다.
- **시한은 120초, 표준 출력 상한은 64 KiB다.** 종료 코드가 0이 아니면 실패이고 표준 오류의 마지막 줄(없으면 표준 출력의 첫 줄)을 이유로 보인다.
  머리말과 프롬프트를 표준 오류로 되울린 뒤 맨 끝에 오류를 적는 명령이 있어 첫 줄이 아니라 마지막 줄을 본다.
- **실행 파일은 이름이나 절대 경로로 적는다.** 이름은 외부 diff 도구와 같은 규칙(앱 폴더, System32, Windows 폴더, PATH의 절대 항목)으로 찾는다.
  `claude`는 npm으로 깔면 PATH에 `claude.cmd`만 놓이므로, 못 찾았을 때 네이티브 설치 자리(`%USERPROFILE%\.local\bin\claude.exe`)와 그 shim이
  가리키는 실행 파일(`node_modules\@anthropic-ai\claude-code\bin\claude.exe`)을 더 본다.
- **`.cmd`·`.bat`는 띄우지 않는다.** cmd.exe를 거치면 인자의 인용 규칙이 달라져 안전하게 넘길 수 없다.

### 보내는 내용

- **켜야만 동작하고, 누를 때만 보낸다.** 설정 `commit_suggestion.enabled`의 기본은 꺼짐이다(Gravatar와 같은 원칙). 꺼져 있으면 커밋 상자에 단추가 없다.
  켜져 있어도 사용자가 단추나 명령을 눌렀을 때만 명령을 띄운다. 저절로 띄우는 일은 없다.
- **프롬프트에 싣는 것**: 고정 지시문(영어), 사용자의 추가 지시 한 줄, HEAD의 최근 커밋 제목 10개, staged 파일 목록과 줄 수, staged 패치.
  출력 언어와 접두어 관례는 최근 제목을 따르게 하고, 커밋이 없는 저장소에서는 화면 언어로 쓰게 한다.
- **패치는 줄여서 싣는다.** 파일 하나에 16 KiB, 전체 96 KiB까지다. 넘으면 `diff --git` 경계에서 자르고 자른 자리를 표시한다. 파일 목록과 줄 수는 늘 온전히 간다.
- **내용을 싣지 않는 파일이 있다.** lock 파일(`*.lock`, `package-lock.json` 등)과 비밀로 보이는 이름(`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa` 등)은
  이름과 줄 수만 싣는다. git이 pathspec(`:(top,exclude,literal)<path>`)으로 빼므로 그 내용은 프롬프트를 만드는 메모리에도 오지 않는다.
  가릴 파일이 200개를 넘으면 패치를 아예 싣지 않고 목록만 보낸다(경로마다 인자 하나라 명령줄 길이에 걸린다). 파일 목록도 200개까지만 적고 나머지는 수로 줄인다.
  **이름으로 가리는 최선 노력이다.** 다른 이름의 파일에 든 비밀은 거르지 못한다 — staged한 것은 곧 커밋할 내용이라는 전제다.
- **답은 그대로 믿지 않는다.** 바깥 코드 펜스와 제어 문자를 걷고 첫 줄을 제목으로, 나머지를 본문으로 입력란에 채울 뿐이다. 커밋은 사용자가 한다.
  패치 안의 글이 모델에게 지시처럼 읽힐 수 있으므로(프롬프트 주입) 프리셋은 모델의 도구를 모두 끈다.

### 프리셋

설정 화면의 프리셋 단추는 실행 파일·인자 칸을 채우는 본보기일 뿐이고 저장되는 "모드"가 아니다. 기본값은 비어 있다.

| 프리셋 | 실행 파일 | 인자 |
| --- | --- | --- |
| Claude Code | `claude` | `-p --safe-mode --tools "" --disable-slash-commands --no-session-persistence --model haiku` |
| Codex | `codex` | `exec --ignore-user-config --skip-git-repo-check --ephemeral --sandbox read-only --color never -` |

- 두 프리셋 모두 도구를 끄고(`--tools ""`, `--sandbox read-only`) 대화를 디스크에 남기지 않는다(`--no-session-persistence`, `--ephemeral`).
- `--safe-mode`는 사용자의 CLAUDE.md·hook·MCP 서버를 빼되 로그인은 그대로 쓴다. `--bare`는 구독 로그인을 읽지 않아 쓰지 않았다.
- `--ignore-user-config`는 사용자의 codex 설정을 뺀다. 설정에 적힌 기본 모델이 계정에서 거절되어 실패하는 경우가 있었다.
- 시험한 판은 Claude Code 2.1.293과 codex-cli 0.164.0이다. CLI의 인자와 기본 모델은 판마다 바뀌므로, 프리셋이 깨지면 사용자가 칸을 고쳐 쓴다.
- **약관은 사용자가 확인한다.** 사용자의 구독으로 도는 CLI를 다른 앱이 띄우는 것을 각 서비스가 어디까지 허용하는지는 이 결정 시점에 문서로 확정하지 못했다.
  cyella는 로그인을 대신 받거나 토큰을 꺼내 쓰지 않고, 사용자가 설치한 명령을 사용자의 설정대로 실행할 뿐이다.

### 실행 경로

- **git operation이 아니다.** 5~30초가 걸리는 일이라 읽기 줄(worker 2개)에 올리면 status·log·diff가 밀리고, 쓰기 줄에 올리면 커밋을 막는다.
  호스팅(ADR-007)처럼 `operation_kind`에 종류를 더하지 않고 `commit_suggestion_job`/`commit_suggestion_result_intent`
  (`application/commit_suggestion_messages.h`)로 오간다. scheduler의 줄 이름은 `commit-suggest:<저장소 id>`다.
- **저장소는 읽기만 한다.** `diff --numstat --cached`, `diff --cached`, `log`를 `--no-optional-locks`의 로컬 조회로 돌린다.
- **사용자가 취소할 수 있다.** 도는 동안 단추가 취소로 바뀐다. 탭을 닫아도 취소된다. 늦게 온 결과는 serial로 가려 버린다.
- **입력란을 덮어쓴다.** 단추를 누른 것이 덮어쓰라는 뜻이다. 다만 기다리는 동안 사용자가 제목이나 본문을 고쳤으면 채우지 않고 알린다.

## 결과

- 비밀이 cyella를 거치지 않는다. 설정 파일에는 실행 파일 이름과 인자, 추가 지시만 남는다.
- 설치된 CLI가 없으면 쓸 수 없다. API 키만 가진 사용자를 위한 HTTP 경로는 따로 정한다.
- amend를 켠 동안은 제안하지 않는다. 비교 기준이 HEAD의 부모로 바뀌어야 하고 amend가 채운 메시지와의 관계를 따로 정해야 한다.
- 프롬프트 전체를 고치는 길은 없다. 한 줄 추가 지시만 받는다.
- 제안 명령은 작업 로그에 남지 않는다(operation이 아니다). 실패 이유는 알림으로 보인다.
