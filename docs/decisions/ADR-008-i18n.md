# ADR-008: 화면 문구는 키로 찾고 언어마다 JSON 파일 하나를 실행 파일에 싣는다

## 상태

승인됨 - 2026-10-22

## 배경

cyella는 공개를 앞두고 있지만 화면 문구가 모두 한국어로 코드에 박혀 있었다(약 1,800개, 97개 파일). 영어 사용자가 쓸 수 있도록
한국어(원문)와 영어를 지원한다. 문구가 presentation만이 아니라 domain(작업 상태·서명 검증·rebase 검사), application(diff 동작
거절), infrastructure(git 오류 해석·설정 경고), platform(프로세스·감시 오류)에서도 만들어지고, 한국어 조사(`을/를`)를 이름에 맞춰
고르는 문장 조립이 있다. 이 셋을 한 규칙으로 다룰 자리가 필요하다.

## 결정

### 카탈로그 계층

- **찾기와 틀 채우기는 domain(`domain/text_catalog.*`)에 둔다.** 계층 규칙상 domain은 아무것에도 의존하지 않으므로, 모든 계층이 쓰는
  문구 함수는 가장 아래에 있어야 한다. 이 파일은 키 → 틀 표(`text_catalog`), 틀 채우기(`format_text`), 프로세스 전역 카탈로그
  (`install_text_catalogs`·`tr`)만 갖고 OS·JSON을 모른다.
- **JSON 읽기는 infrastructure(`json_text_catalog.*`), resource 읽기와 시스템 언어는 platform(`win32_locale.*`)이다.** 앱 설정을
  읽는 구조와 같다.
- **코드는 `tr(u8"area.name")`·`tr(u8"area.name", { { u8"arg", value } })`로 쓴다.** `std::string`(UTF-8 바이트)을 받는 자리는
  `tr_narrow`다. 정수 인자는 십진 표기로 바뀐다.

### 문구 파일

- **언어마다 평평한 JSON object 하나다**(`assets/locales/ko.json`, `en.json`). 키는 `영역.이름`(소문자 snake_case, 점으로 가른다.
  예: `menu.reset_soft`, `settings.general.theme_help`)이고 값은 틀 문자열이다. 키 순서는 사전순으로 둔다.
- **실행 파일에 RCDATA(109·110)로 싣는다.** 설치·배포할 파일이 늘지 않고, test 실행 파일도 같은 `.rc`를 실어 앱과 같은 길로 읽는다.
  파일을 고치면 `.rc`가 다시 컴파일되도록 `OBJECT_DEPENDS`에 넣는다.
- **찾는 순서는 고른 언어 → 한국어 → 키 자신이다.** 한국어 파일은 늘 바탕으로 깔고 영어를 그 위에 얹는다. 영어 번역이 빠진 키는 한국어
  원문으로 보이고, 둘 다 없으면 키가 그대로 보여 빠진 것이 화면에서 드러난다.

### 틀 문법

- `{name}`은 인자 값이다. 없는 인자의 자리는 틀 그대로 남는다.
- `{name|을/를}`은 값 뒤에 받침에 맞는 조사를 붙인다(`은/는`·`이/가`·`과/와`도 같다). `{name|으로/로}`는 ㄹ 받침도 `로`다. 받침 짐작은
  예전 `korean_josa`의 규칙(한글 음절, 영어 끝 글자 n·m·l, 숫자 0·1·3·6·7·8)을 그대로 쓴다. 영어 틀은 같은 인자를 `{name}`으로 쓰고
  어순을 마음대로 바꾼다(`{what|을/를} {to|으로/로} reset` ↔ `Reset {what} to {to}`).
- `{{`·`}}`는 중괄호 한 글자다.
- **복수형 문법은 만들지 않는다.** 영어에서 수에 따라 꼴이 바뀌는 문장은 `…_one` 키를 따로 두고 코드가 `count == 1`로 고른다. 한국어
  값은 둘이 같다. 가능하면 수에 기대지 않는 문장(`Commits: 3`)으로 쓴다.
- **문장을 조각으로 번역해 이어 붙이지 않는다.** `이름 + "을 " + 대상 + "에 merge"` 같은 조립은 인자 있는 틀 하나가 된다. 독립된 덧말
  (` · 이미 포함`)처럼 어순과 무관한 꼬리만 따로 둔다.

### 언어 고르기

- 설정 파일 최상위 `language`가 `system`·`ko`·`en`이다(기본 `system`). 환경 설정의 일반 페이지에서 고른다.
- `system`은 `GetUserDefaultUILanguage()`의 주 언어가 한국어면 한국어, 아니면 영어다. 공개 앱이라 한국어가 아닌 시스템의 기본은 영어다.
- **바꾸면 다시 시작할 때 적용한다.** 카탈로그는 `wWinMain`이 창·driver·작업 thread를 만들기 전에 한 번 정한다(설정 파일에서 언어만
  먼저 읽는다). 그 뒤로는 읽기만 하므로 thread 사이에 잠금이 필요 없고, 한 번 만들어 두는 표(명령 레지스트리 등)와 작업 thread가 이미
  만든 문구가 언어를 섞지 않는다. 화면 전체를 다시 만들며 바꾸는 방식은 이 두 문제를 모두 풀어야 해서 얻는 것에 비해 위험이 크다.
- test는 Catch2 listener가 시작할 때 한국어를 정한다. 기존 test가 비교하는 한국어 문구가 그대로 맞는다.

### diff 뷰어

- 뷰어(`assets/diff-viewer/*.js`)의 문구도 같은 파일의 `diff_viewer.*` 키다. 앱이 내용보다 먼저 `set_strings` 메시지로 그 키들을 보내고,
  JS는 `t('diff_viewer.name', { arg })`로 찾는다. 받기 전이거나 없는 키는 키 자신이다. 문서 `lang`도 그 메시지가 정한다.

### 옮기지 않는 것

- 코드 주석, git·ssh·gpg 출력을 해석하는 원문 매칭 문자열, 파일·설정·git에 남는 값(설정 키, enum 이름, 명령 id, 커밋·stash 메시지
  기본값처럼 저장소에 기록되는 문자열), UI Automation owner 이름(요소 id), 한글 초성 검색 표.
- 이미 영어인 고유 명칭(`Cherry-pick`, `Push…`, `Stage`)은 한국어 화면에서도 영어라 그대로 둔다.

### 검사

- `tests/locale_catalog_tests.cpp`가 실린 두 파일을 앱과 같은 길로 읽어 다음을 확인한다. 둘 다 문제 없이 읽히고(같은 키 두 번, 문자열이
  아닌 값 없음) 키 집합이 같다. 키마다 두 언어의 틀이 같은 인자 이름을 쓰고 중괄호가 맞다. `src/`의 `tr(u8"…")`·`tr_narrow(u8"…")`와 뷰어의
  `t('…')`가 쓰는 키가 모두 있고, 아무도 쓰지 않는 키가 없다.
- 그래서 **키는 늘 호출에 문자열 상수로 바로 적는다.** 키를 이어 붙여 만들거나 변수로 넘기지 않는다. 표에 키를 담아야 하면 표를
  만들 때 `tr`을 부른다.

## 결과

- 문구를 고치거나 더할 때 두 JSON 파일을 함께 고친다. 빠뜨리면 키 검사 test가 실패한다.
- domain이 화면 문구를 만드는 구조(작업 상태의 사용자 메시지 등)는 그대로다. 오류를 코드로 돌려주고 presentation이 문구로 바꾸는 편이
  계층상 깨끗하지만, 이번 범위는 문구 이동이다.
- 영어는 한국어보다 길어지는 문구가 많다. 고정 폭 자리(단추, 칩)는 영어로 확인한다.
- 언어를 더하려면 `ui_language`·`language_preference`에 값을 더하고, 파일과 resource ID를 하나 늘리고, 필요하면 그 언어의 꼴 규칙을
  틀 문법에 더한다.
